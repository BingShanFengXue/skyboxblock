# 核心方块、附属模组与兼容性总体注意事项

日期：2026-10-19。基线：Minecraft 1.21.1 / Fabric，`skyboxblock 1.0.2-test.4`。

**文档性质：开发方向与验收约束。本文没有实现新的维度规则、附属 API 或门户兼容；不得将规划内容当作现有功能。**

## 1. 总体决定

1. **先做好现有这一个原版风格天空方块。** 主模组维持 `skyboxblock:sky_block`，本阶段不恢复已经删除的多套预设方块。
2. **后续其他天空内容优先作为一个可选附属模组扩展。** 附属模组依赖主模组；主模组单独安装也应完整可用。先做一个内容扩展包即可，不必为每种天空各建一个独立模组。
3. **渲染内核共用，天空内容分离。** 附属模组注册方块、资源、外观参数或内容提供者，不复制主模组的世界绘制、Iris 适配和状态保护。
4. **下一项工程按最新安排转为沉浸式传送门兼容尝试。** 这是探索性兼容，不预设最终一定全面成功，也不将全部门户特性作为核心方块稳定发布的硬前提。
5. 先通过门户试验明确多视图边界，再收敛正式附属 API；本阶段避免为尚未出现的附属内容做大规模预重构。
6. NeoForge / Sinytra Connector 保持“未实测、非强制目标”；不并入这次开发主线。

## 2. 稳定性与效果：拆包本身不是问题

**可行，且通常更利于控制主模组的改动面。** 一个 jar 还是两个 jar 并不直接决定画质或稳定性；主要取决于是否共用渲染路径、资源生命周期和清晰的版本契约。

| 方式 | 预期影响 |
|---|---|
| 附属仅注册内容，调用主模组公开入口 | 已修复的遮挡、FSR、状态恢复等集中维护；更容易保持一致 |
| 附属复制一套渲染器、Mixin、Iris 反射适配 | 修复分叉、重复绘制、状态相互覆盖，稳定性风险显著增加 |
| 每个方块都单独生成一套全尺寸天空目标 | 方块越多资源越多，容易出现显存和帧时间问题 |
| 同一视图按外观分批，共用有界缓存 | 成本主要随可见内容组数和视图数增长，而非方块数量线性堆积 |

“效果一致”应分两种理解：

- **同一种外观**：相同相机、时间、方块位置、资源和渲染设置下，由主模组或附属方块调用，投影、遮挡、颜色和持物保护应保持一致。
- **不同外观**：颜色、贴图和天体布局可以不同，但几何对齐、连续方向投影、深度和世界前景保护应沿用同一套规则。

共享内核会降低重复修复成本，但不等于任意新增着色器、资源包或第三方组合自动通过验收。

## 3. 当前实际实现及其扩展限制

当前代码已经完成单方块渲染，并非现成的通用附属 API。

| 当前实现 | 扩展时的注意事项 |
|---|---|
| [方块类](<../src/main/java/dev/yg/skyboxblock/SkyBlock.java#L12-L18>)和[方块实体类](<../src/main/java/dev/yg/skyboxblock/SkyBlockEntity.java#L10-L17>)为 `final` | 不是直接继承现有两个类就能接入附属方块 |
| [注册逻辑](<../src/main/java/dev/yg/skyboxblock/SkyboxBlockMod.java#L31-L43>)只登记一个方块及其方块实体类型 | 新类型需要正常登记，避免依赖运行后修改既有注册结构 |
| [客户端入口](<../src/main/java/dev/yg/skyboxblock/client/SkyboxBlockClient.java#L11-L20>)只绑定主模组这一种方块实体渲染器 | 需要公开参与渲染的注册入口或桥接工厂 |
| [世界绘制](<../src/main/java/dev/yg/skyboxblock/client/SkyWorldRenderer.java#L32-L54>)每个视图只有一组几何集合；[收集入口](<../src/main/java/dev/yg/skyboxblock/client/SkyWorldRenderer.java#L103-L113>)接收具体的 `SkyBlockEntity` | 多外观需要按内容键分组，入口应与具体主模组方块实体类型解耦 |
| [天空生成器](<../src/main/java/dev/yg/skyboxblock/client/VanillaSkyScene.java#L18-L27>)保存一对世界 / 显示天空目标 | 未来按外观和视图隔离或调度复用，避免全局纹理串用 |
| [最终颜色恢复](<../src/main/java/dev/yg/skyboxblock/client/SkyWorldRenderer.java#L174-L183>)仅围绕根视角和主目标执行 | 门户内部仍是明确的适配缺口，单纯拥有视图栈不等于门户兼容完成 |

相邻面的剔除也要纳入接口设计：当前按邻居是否为 `SkyBlock` 判断。以后应明确定义同外观、异外观以及不同形状之间的共享面规则。完整实心立方体内部的不可见面仍可剔除，不应为了类型不同就无条件增加内面。

## 4. 已确认的核心方块效果规则

以下来自后续讨论，**属于已确认目标，尚未在 test.4 全面实施**：

### 4.1 外观与维度分离

- 所有维度中的核心方块都显示**主世界风格的天空**，不是复刻所在维度的天空。
- 在末地、下界及其他维度中，也应拥有该套主世界风格的背景、日月星和云，而不是继续切成末地背景或下界雾。
- 固定的是外观体系，不是要求天空永远白天，也不是读取光影包外部天空。
- 天空仍独立生成，不恢复已删除的世界颜色抓帧路线。

### 4.2 时间来源采用条件规则

| 环境 | 目标时间来源 |
|---|---|
| 原版主世界 | 跟随实际天空时间；睡眠跳夜、时间指令等应同步体现 |
| 模组创建的类主世界维度 | 跟随该维度自身实际天空时间 / 相位，尊重偏移、昼夜速度或固定时间 |
| 下界、末地等非常规天空维度 | 使用备用模拟时钟驱动主世界风格天空 |

注意：

- 独立绘制不等于始终独立计时。只改变天空盒显示，不改动真实世界时间或玩法规则。
- 不仅按维度 ID 或“有天光”分类；结合天空效果和实际时间机制判断，并为特殊维度保留明确覆盖入口。
- 日照颜色、太阳 / 月亮位置、星星显隐、月相及云的昼夜颜色应读取一致的显示状态，避免一部分用模拟时间、另一部分继续用目标维度参数。
- 对没有主世界天空的目标维度，避免直接混入末地 / 下界的雾色、亮度和天体显隐规则。
- 备用时钟的初始值、持久化、离线推进以及多人同步方式尚待明确；不得暗自演变成每块方块各走各的时钟。
- 天气采用当地、指定来源或独立模拟的具体规则尚未确认，应与时间来源分开设计。

### 4.3 云层

- 核心外观的名义云高保持原版 **Y=192**，保留原版几何偏移及立体厚度。
- 目标是所有维度均能显示该外观所需的云；未来云是否存在应由外观策略决定，而不是被所在维度的 `SkyType` 一概关闭。
- 当前[云层实现](<../src/main/java/dev/yg/skyboxblock/client/SkyVanillaClouds.java>)仍仅在普通天空维度绘制；这是现状与后续目标之间的差距，不应写成已经完成。
- 云应保留水平漂移与昼夜 / 天气响应。

当前[天空生成器](<../src/main/java/dev/yg/skyboxblock/client/VanillaSkyScene.java#L62-L83>)仍读取实际维度的时间、天空 / 雾色和天空类型。以后实现上述规则，需要统一抽取“显示天空状态”，而非仅替换太阳角度。

## 5. 主模组与附属模组的职责边界

### 主模组负责

- 核心 `sky_block` 及其稳定的注册 ID、方块行为和默认资源。
- 世界空间几何收集、面剔除、连续方向投影、批次调度和深度遮挡。
- 世界阶段与最终颜色合成的时序。
- Iris / FSR / TAA 及后续门户兼容适配。
- GL 真实状态、Minecraft 缓存状态、Iris 逻辑状态的成对恢复。
- 天空目标、深度纹理、网格、缓存池与资源重载 / 断线清理。
- 默认的主世界风格内容、时间策略，以及稳定的扩展注册入口。

### 附属模组负责

- 自身命名空间下的新方块、物品、配方、战利品、语言和美术资源。
- 注册新的天空内容提供者和必要的外观参数。
- 通过公开工厂或参与接口接入主模组的统一渲染。
- 声明支持的主模组 API / MC 版本，并为自己的资源和效果补充验收。

### 避免的做法

- 将主模组代码打包进附属 jar，造成重复内核或类冲突。
- 附属再注入一套相同的世界渲染 Mixin，或单独维护 Iris 私有字段反射。
- 绕过主模组状态保护，随意绑定全局目标、改变全局矩阵或恢复错误的世界状态。
- 覆盖核心 `skyboxblock:sky_block` 的注册 ID，或把卸载附属内容变成基础方块消失。

## 6. 后续 API 的最小设计方向

以下均为**拟议职责，不是现有可调用接口**。正式命名、签名和版本在核心多视图路径稳定后确定。

| 概念 | 作用 |
|---|---|
| 外观键 / 外观定义 | 稳定的命名空间 ID、内容参数、资源及能力描述 |
| 天空内容提供者 | 在主模组分配的绘制范围内生成天空，不接管整个世界合成流程 |
| 只读视图上下文 | 当前目标世界、实际相机、投影、裁剪信息、尺寸与显示天空状态 |
| 时间来源策略 | 当地天空同步或备用模拟时间，与天空外观解耦 |
| 方块参与入口 | 将附属方块的面和外观键交给统一收集器，不依赖具体 `SkyBlockEntity` 类型 |

约束：

1. 普通注册 / 存档数据与客户端渲染接口分离，专用服务端加载普通类时不触及客户端 GL 类。
2. 上下文不把可随意改写的核心矩阵和全局资源直接交给附属；必要时提供只读视图或副本。
3. 内容提供者在受控渲染线程和状态作用域中执行；资源缺失或单个提供者异常应有可观察的回退，并确保状态收束。
4. 新外观若仍是完整立方体的无限远天空，可复用当前几何路径。半砖、特殊形状、近景视差或真实三维景物属于额外能力，需单独设计和验收。
5. 暂不为尚未确定的需求承诺通用插件系统或无限制自定义渲染回调。

## 7. 多外观与多视图的稳定性约束

- 同一视图按“外观键 + 有效参数”分组；一个组生成的天空可供该组多个方块使用。
- 相机、矩阵、门户裁剪面、镜像方向、深度来源和目标尺寸都属于视图上下文，避免主视角覆盖门户子视角。
- 缓存要有清理与容量边界。稳定键可以包含内容、资源修订、目标维度、视图槽位和尺寸；时间、相机运动和抖动通常作为刷新输入，避免每个浮点变化都创建永久缓存项。
- 资源重载后失效并重新绑定相关资源；窗口缩放、切换光影、断线和退出时清理自有目标与深度纹理。
- 实际 GL viewport 与光影有效光栅继续分开维护，避免 FSR 重复缩放。
- 深度属于对应视图 / 绘制阶段，禁止拿上一帧、另一维度或主相机的深度去验证门户内的天空。
- 新提供者或门户逻辑不应重新引入世界颜色抓帧、CPU/NDC 覆盖几何，或放大前景排除区来掩盖错位。
- 优先保证不污染外部世界的实体、选择框、持物和其他模组，再讨论某个天空效果是否更华丽。

## 8. 版本、存档与部署

- 附属声明对主模组及其 API 版本的依赖。模组版本与公开 API 契约要有可识别的兼容范围。
- 公开 API 变动时写迁移说明，避免附属直接调用内部静态字段来绕过版本边界。
- 核心方块 ID 保持稳定；附属资源使用自己的命名空间。
- 附属新增实体方块等注册内容时，客户端与服务端需安装匹配内容；纯美术资源包与新增注册项是两种部署模式。
- 卸载附属可能留下缺失注册项，这是新增方块的存档生命周期问题。主模组独立可用不等于卸载附属后所有附属方块自动迁移。
- API / 附属开发前保留已经验收的核心 jar 和源码快照，试验版本与稳定交付分开。
- 本轮文档不改变现有 MIT 许可及来源标注；新增美术或第三方资源另行记录许可。

## 9. 下一步：沉浸式传送门兼容尝试

### 9.1 先确定故障属于哪一层

使用隔离新世界，分别建立：

1. Iris / Sodium + 沉浸式传送门，**不安装本模组**的基础组合基线。
2. 相同组合安装本模组，但场景中没有天空方块。
3. 相同组合存在可见天空方块。

先无光影，再 ITRP 关闭 FSR2，最后保留用户 `FSR2_SCALE=2` 的配置。固定版本、资源包、相机、世界和光影设置，并保存各组清单与哈希。

这样区分基础组合本身的问题、天空模组空场景的全局影响，以及真正的天空绘制问题。不要在缺少对照时把所有故障归给一个模组。

### 9.2 分层推进，逐项记录支持程度

| 层级 | 试验目标 |
|---|---|
| A | 没有门户时，现有单方块与全部既有回归保持稳定 |
| B | 同维度单门户：隔门观察天空方块，验证相机、深度、裁剪和最终颜色 |
| C | 穿门及往返：视图切换后无残留、错位、串维度状态 |
| D | 跨维度单门户：先区分维度内容规则未实施与门户绘制故障 |
| E | 多门户、镜像、不同尺度、嵌套视图；分别声明实测范围 |

当前[最终合成入口](<../src/main/java/dev/yg/skyboxblock/client/SkyWorldRenderer.java#L174-L183>)只处理根视角。试验重点是找到每个门户视图真实的绘制目标、Iris 合成时序和深度归属，而不是简单取消 `portal` 判断后统一画到主屏幕。

[Iris / 门户适配](<../src/main/java/dev/yg/skyboxblock/client/ModCompat.java>)已有部分检测、矩阵与裁剪支持，但这些基础设施本身不是兼容完成的证据。嵌套退出时继续按进入前原值恢复逻辑状态，尤其保留 test.4 的 `isMainBound` 修复。

### 9.3 每层都要看的判据

- 透过门户的天空方向和相机一致，无画面拉伸、串视角或串维度。
- 远端实体、掉落物、选择框和地形有正确位置与深度遮挡。
- 手部与门户边界被正确保留；最终颜色与相应视图的独立天空参考匹配。
- FSR / TAA 的比例、抖动和深度映射来自正确视图。
- 缩放、资源重载、切换光影、穿门往返后状态仍正确。
- 未显示天空方块时，对原世界与门户的表现没有额外干扰。
- 增加实际位置与视图归属断言，不把“程序正常退出”或“某处出现了天空”当成验收。

### 9.4 试验出口

- 若某层通过，写清确切版本、光影包、FSR 模式和场景范围，继续下一层。
- 若卡在基础组合或缺乏可靠合成接入点，保留最小复现、日志和具体缺口；收敛为已验证的部分支持，避免无限扩大试验。
- 试验版本单独交付，已验收的单方块基线保持可回滚。对子项的放行不自动外推到全部门户功能。

## 10. 回归与“效果一致”的验收

现有基线见[项目说明](<../README.md>)、[test.4 修复记录](<IRIS-STATE-TEST4-2026-10-19.md>)与[最终验收数据](<../build/reports/state-test4-final-acceptance.json>)：三环境共 111 场景、1,468 项图像 / 深度 / 位置检查；数学断言 65,018 项。

后续验收分两层：

- **当前基线不退步**：继续复核天空颜色、世界面覆盖、非活动光栅污染、手部保护、掉落物中心和选择框实际投影，以及资源重载 / 缩放。
- **新增能力有新用例**：维度 / 时间规则、门户视角和将来多外观分别新增场景，不用旧的通过数替代新能力验收。

附属 API 发布前至少验证：

- [ ] 只装主模组，原有方块和存档行为保持正常。
- [ ] 使用最小测试附属，以同一默认内容提供者渲染另一种方块。
- [ ] 在相同相机、时间、位置和资源下替换方块，比较相同可见天空区域；记录像素容差与实际误差，排除光影历史帧差异。
- [ ] 两种外观同屏、相邻和被遮挡时不串纹理、不重复绘制、不错误剔面。
- [ ] 所有外观共用同一套持物、掉落物和选择框位置回归。
- [ ] 资源缺失、重载、窗口缩放、切换光影、断线重连后的资源生命周期正确。
- [ ] 专用服务端加载及客户端 / 服务端注册项匹配。
- [ ] 已明确支持的门户范围，在主模组与最小附属中分别验证。

历史 [test.4 源码与证据快照](<../../artifacts/snapshots/skybox-test4-state-alignment-20261019-final.zip>)保持原样。该历史快照早于本文，不包含本文的新规划；后续代码试验另存新快照。

## 11. 后续接手时的简短规则

> 先稳定一个核心方块；天空外观与时间来源解耦；渲染和兼容修复只维护一套。下一项是门户兼容探索，而不是增加预设。门户多视图边界稳定后，再公开最小扩展接口，用一个依赖主模组的附属扩展其他天空内容。所有“已支持”结论以对应场景的实测为准。
