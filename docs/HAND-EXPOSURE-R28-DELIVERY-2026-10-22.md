# test.8 / R28：密闭天空墙内手臂渐白修复

日期：2026-10-22（Asia/Shanghai）。项目作者：Bing6512。Minecraft 1.21.1 / Fabric / Java 21。

**结论：原生与FSR的手部渐白专项修复已通过，交付test.8测试候选；全套渲染验收仍未通过。透明层保留5项移除恢复差异和4项水层参照证据不足，未豁免、未改绿，不宣称正式发布放行。**

## 1. 现象、根因与最小修复

原实现靠近大面积天空墙时就可能开始漂白，进入626个天空方块组成的密闭外壳后，原生和FSR均在数秒内出现纯白手臂。晚期测光平均亮度达到RG16F半浮点上限 **65504**；独立深度选出的手部像素白色占比达到 **100%**。退出但仍看着天空墙时也可继续受影响，移除天空墙后恢复。

同位置、同光影选项的玻璃外壳正常。真实天光始终15、方块光0；最终天空颜色恢复前后，手部像素逐像素不变，排除“最后一遍天空直接盖掉手臂”的解释。

精确ITRP的 `Exposure_CS` 把平均场景亮度存入 `pixelData2D.r`，实际曝光倍率存入 `.g`；最终颜色和FSR阶段使用 `.g`。旧桥接把显示天空线性RGB乘以 `.r*0.13`，当天空占据大部分测光画面时形成增幅反馈，最终饱和并通过光影后处理漂白手臂。

生产修复仅在[背景片段](<../src/main/resources/assets/skyboxblock/shaders/core/sky_material_background.fsh>)把换算调整为：

```text
HDR sky input = linear generated sky RGB / actual exposure multiplier (.g)
```

并守卫无效初始倍率。**泛光、自动曝光保持开启**；没有钳制全局曝光、替换皮肤、改变碰撞/世界实际光级或修改光影ZIP。显示天空仍由本模组独立生成，生产代码没有读取目标世界RGB。

与同诊断工具的旧实现包相比，JAR唯一变化条目是 `assets/skyboxblock/shaders/core/sky_material_background.fsh`。`SkyBlock`、`SkyWorldRenderer`、`SkyGlState`、`VanillaSkyScene`、`SkyVanillaClouds` 和 `ModCompat` 的class与test.7逐字节相同。[源码差异及哈希](<../build/reports/r28-source-delta.json>)、[补丁](<../build/reports/r28-implementation.patch>)。

## 4. 原始诊断全部保留

1. 初版检查器把“向服务器请求移除后首帧”当作“客户端已确认移除”，旧原生127/128、候选R2也记录626块原壳。首帧定义现已明确为请求态，保留实际计数；10秒后仍严格要求实际0块。颜色、曝光、GL和晚期恢复阈值未改变。
2. 候选R2有1条Yggdrasil公钥请求联网ERROR，原日志及初次报告保留；同一冻结候选原生R3重跑无该ERROR，没有把原错误归零。
3. 原生R3初次177/178仅因Iris重写配置首行时间注释，导致原始SHA不同。原报告保留；当前要求全部解析选项、其余fixture声明、实际光影ZIP和辅助模组字节一致，原始SHA仍记录。语义相同后180/180，而不是忽略真实设置变化。
4. 原版完整组R3在2.923秒出现JVM本地ZGC线程 `EXCEPTION_ACCESS_VIOLATION`，0场景，原 `client.log`、`hs_err_pid14528.log`及退出1保留。旧扫描器未识别此类fatal文本，另建[真实诊断](<../build/reports/r28-jvm-startup-diagnostic.json>)并补充扫描器；不会因旧数组为空就宣称该次无致命异常。同一候选、同一JVM/游戏参数重试R4成功完成113场景，fixture声明逐项相同；其透明检查5项仍红，因此重试汇总没有被改成整批通过。未据此修改生产Java代码，也未宣称JVM问题已修复。
5. 首轮批次的非零退出与全部透明层红项保留，严格最终报告分开给出“手部修复验证”“其他候选检查”“未结案项”，不使用单一绿标覆盖失败。
