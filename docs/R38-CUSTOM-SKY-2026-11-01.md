# R38 自定义天空盒 + 按玩家设置

版本 `1.0.5-test.1-r38`，基线为 R36（`1.0.4-test.2-r36`）。

---

## 1. 自定义天空盒

### 1.1 目录

```
<gameDir>/config/skyboxblock/skyboxes/      ← 只读，mod 仅创建不覆盖
   00_example.conf                           ← 首次生成，enable = false
   example_white.png / example_black.png     ← 首次生成的示例全景
   <你的全景>.png
   <你的配置>.conf
<gameDir>/config/skyboxblock/generated/      ← mod 生成：pack.mcmeta、blockstate/model、羽化后的贴图
```

目录**不递归**；只接受 `.conf` 与 `.png`；单文件 ≤ 64 KB、≤ 64 个配置、≤ 64 种风格、单图 ≤ 4096×2048 / 16 MB。

### 1.2 配置语法

```conf
# 注释到行尾；引号内的 # 不是注释
enable = false          # 总开关；false 时完全不扫描、不注册

test_sky_block_1 = {
    id = "skyboxblock:test_sky_block_1"     # 必填，ASCII
    picture = "全景图.png"                    # 必填，只允许文件名
    creative_inventory = true               # 可选，默认 true
    lang_zh_cn = { name = "测试天空盒1" }     # 可选，任意 MC 语言码
    lang_en_us = { name = "Test Sky Block" }
}
```

| 键 | 规则 |
|---|---|
| `id` | `^[a-z0-9_.-]+:[a-z0-9_./-]+$`，重名保留先出现的 |
| `picture` | 必须 `.png`；不得含 `/`、`\`、`.`、`..`；不得为空串 |
| `creative_inventory` | `true/false`，兼容 `yes/no` |
| `lang_<code>` | `<code>` 匹配 `^[a-z]{2,3}(_[a-z]{2,4})?$`；块内只能有 `name` |
| 未知键 | WARN + 忽略 |
| 花括号/引号不闭合、缺 `=` | **整个文件**放弃 |
| 缺 id/picture、值非法 | 只跳过该块 |

语言名回退链：精确码 → 语言段 → `en_us` → `en` → id 的路径部分。

### 1.3 纹理处理

- 载入时对左右边缘做 8 像素羽化（`periodic` 思路），避免手作素材出现竖缝
- 非 2:1 的图仍接受，但日志 WARN 一句
- 生成 32×32 方块图标（全景中心裁切），用于物品栏

### 1.4 资源注入方式

Fabric 的内建资源包只能读 mod jar 内的文件，而这里的资源在用户目录，且 1.21.1 的
`PackRepository` 选择列表在 reload 后是只读快照。因此
`mixin/CustomSkyPackMixin` 注入 `MultiPackResourceManager` 的构造函数，
把生成的包直接并入每次资源加载：

```text
config/skyboxblock/generated  ──►  CustomSkyPack (PackResources)
                                        │
              MultiPackResourceManager.<init>(type, packs + 本包)
                                        ▼
          blockstate / model / texture / lang 与 jar 内资源等价
```

不写 `options.txt`，不改动玩家设置。

### 1.5 一致性

- manifest hash = 排序后的 `id + picture`（**语言名不参与**）
- 客户端/服务端 id 集合不一致时给出明确差异提示，而不是 MC 的 missing registry 报错
- `enable = false` → 空集合 → 与纯原版一致，**不会因为配置不同进不去**

## 2. 指令

### 2.1 客户端（打开目录）

| 指令 | 作用 |
|---|---|
| `/skyboxcustom` | 打开 `config/skyboxblock/skyboxes/`，聊天里给可点击路径 |
| `/skyboxcustom list` | 列出已加载风格 + 被跳过的文件与原因 |

### 2.2 按玩家设置（服务端，权限等级 2）

```
/skyboxblock player <targets> show
/skyboxblock player <targets> set <attribute> <value>
/skyboxblock player <targets> reset <attribute|all>
/skyboxblock player <targets> time set <0-24000>
/skyboxblock player <targets> time reset
```

- 存储：`world/serverconfig/skyboxblock-players.properties`，键 `player.<uuid>.<key>`
- 生效值 = 全局属性 + 玩家覆盖，再走同一套校验
- 同步：不再广播，逐个玩家发送**他自己**的快照（登录时同样按其覆盖发送）
- 默认**跟随服务器**，只有显式 `set` 才有独立值

## 4. 已知限制

1. 自定义方块在**启动时**注册，改配置必须重启游戏（不做热加载）
2. 客户端与服务端的 `skyboxes/` 内容必须一致；否则按 manifest 差异拒绝并提示
3. 世界存档里已有的自定义方块，若从配置中删除对应 id，会变成空气（MC 对未知 palette 项的处理）
4. 资源注入依赖 `MultiPackResourceManager` 构造点，未来 MC 版本若改变该流程需要重新适配
5. 按玩家设置只影响**显示**：模组从不写 `setDayTime` / `setWeatherParameters`，光照与刷怪仍按真实世界状态
