## 0. 三条最关键的更正（先看这个）

1. **`ResourceLocation` → `Identifier` 不是 26.2 的改动。**
   26.1.2 的官方示例代码里已经在用 `net.minecraft.resources.Identifier`（[CustomRenderPipeline.java（26.1.2）](https://github.com/FabricMC/fabric-docs/blob/-/reference/26.1.2/src/client/java/com/example/docs/rendering/CustomRenderPipeline.java)，证据级 **C**）。
   → 回迁 26.1 时这个改名工作量为 **0**。改名的准确发生点（1.21.11 还是 26.1）**待实测**（拿 1.21.11 client jar `jar tf` 一次即可定案）。

2. **`ShaderInstance` 消失、`RenderSystem` 状态 API 清空，同样是 26.1 时代完成的，不是 26.2。**
   26.1.2 已是「`RenderPipeline` 声明式 PSO + `ShaderManager` 统一编译」范式（[26.1.2 渲染管线分析](https://github.com/tt432/eyelib/blob/2b653dceb9e3db871851949545a5deddfdd8645a/docs/vanilla_research/geo_render/26.1.2.md)，证据级 **D**；旁证：26.1.2 官方示例直接用 `RenderPipeline`/`RenderPass`，**C**）。
   → 这意味着「回迁 26.1」**不需要把渲染架构退回 1.21.1**，差距是窄的（见 §2.1）。精确到方法级的 `RenderSystem` 差集**待实测**。

3. **26.3 才是真正的大地震。** 26.3 把整个 `com.mojang.blaze3d.*` 渲染栈搬到 **Renderpearl**（`com.mojang.renderpearl.api|backend|frontend.*`），并删掉 `RenderSystem#outputColorTextureOverride` / `#outputDepthTextureOverride`（[26.2 → 26.3 primer](https://docs.neoforged.net/primer/docs/26.3/)，**B**）。
   → 本模组「抓当前帧 → 换 framebuffer」的骨架正好踩在这两条上：26.3 不是改包名，是**换机制**。

**怎么读这张表（对移植的直接含义）**：

- 格式号自 25w31a 起改为 `主版本.次版本` 两段式，且 `pack.mcmeta` 用 `min_format` / `max_format` 而不是 `pack_format`（[Pack format §Technical details](https://minecraft.wiki/w/Pack_format)，**A**）。→ 模组的 `pack.mcmeta` 必须写 `min_format/max_format`，写老字段在 26.x 上不认。

- **26.3 的 9 次 bump（88→97.1）** 才是真 breaking：shader 语法（`#include` + 强制 `layout(location)`）、`text_background` 合并进 `text`、`armor_trims` 图集删除、纹理 palette 元数据、`post/transparency.json` 删除。见 §3.3。
- 逐版本变更的完整列表可查 [Misode 版本 changelog](https://misode.github.io/versions/?id=26.3&tab=changelog)（primer 官方指向它）。

## 2. 26.1 → 26.2 的模组开发面变更清单

### 2.0 方法论：用「同一份官方示例」做 diff

`fabric-docs` 为每个版本各留了一份内容相同的示例（`reference/26.1.2/…` 与 `reference/latest/…`）。同一份 `CustomRenderPipeline.java` 在两版之间的差异，就是 26.1→26.2 渲染面的**最小可编译差集**（证据级 **C**）：

| 关注点 | 26.1.2 写法 | 26.2 写法 |
|---|---|---|
| 顶点缓冲 | `new BufferBuilder(ALLOCATOR, mode, format)` + `MeshData.buildOrThrow()` + `MappableRingBuffer` + 手动 `commandEncoder.mapBuffer(...)` + `MemoryUtil.memCopy(...)` | `StagedVertexBuffer(() -> "…", RenderType.SMALL_BUFFER_SIZE)` + `appendDraw(format, topology, sorting)` + `getVertexBuilder(draw)` + `upload()` + `getExecuteInfo(draw)` + `endFrame()` + `close()` |
| 索引 | `pipeline.getVertexFormat().uploadImmediateIndexBuffer(...)` / `RenderSystem.getSequentialBuffer(mode)` | 由 `StagedVertexBuffer$ExecuteInfo` 统一给出 `indexBuffer()/indexType()/firstIndex()/baseVertex()` |
| 取顶点格式 | `pipeline.getVertexFormatMode()` / `getVertexFormat()` | `pipeline.getVertexFormatBinding(0)` / `getPrimitiveTopology()` |
| pass 创建 | `createRenderPass(name, colorView, **OptionalInt.empty()**, depthView, OptionalDouble.empty())` | `createRenderPass(name, colorView, **Optional.empty()**, depthView, OptionalDouble.empty())`（第 3 参变 `Optional<GpuTextureView>` → **MRT**） |
| 顶点绑定 | `renderPass.setVertexBuffer(0, GpuBuffer)` | `renderPass.setVertexBuffer(0, info.vertexBuffer().slice())`（`GpuBufferSlice`） |
| draw 调用 | `drawIndexed(baseVertex, 0, indexCount, 1)` + `builtBuffer.close()` | `drawIndexed(indexCount, 1, firstIndex, baseVertex, 0)`（**5 参，第 5 个是 firstInstance**） |
| 矩阵 | `RenderSystem.getModelViewMatrix()` | `RenderSystem.getModelViewMatrixCopy()`（前者被改名/收紧） |
| 主 target | `client.getMainRenderTarget()` | `client.gameRenderer.mainRenderTarget()` |

> 这份 diff 是本次调研**最有价值的单件证据**：它同时给出了「哪些类没了」「参数顺序变了」「谁接管了谁」。完整两份源码：
> [26.1.2 版](https://github.com/FabricMC/fabric-docs/blob/-/reference/26.1.2/src/client/java/com/example/docs/rendering/CustomRenderPipeline.java) / [26.2 版](https://github.com/FabricMC/fabric-docs/blob/-/reference/latest/src/client/java/com/example/docs/rendering/CustomRenderPipeline.java)。

### 2.1 渲染（26.1 → 26.2）

> 前置事实（重要）：26.1 已经是 `RenderPipeline` + `RenderPass` + `GpuDevice` + `FrameGraphBuilder` + `SubmitNode` 范式，**只有 OpenGL 后端**。26.2 做的事是「把这套抽象**泛化到能跑 Vulkan**」，而不是「从状态机改成管线」。

#### 2.1.1 类级变动表

| 类别 | 26.1 现状 | 26.2 变动 | 影响本模组 |
|---|---|---|---|
| 后端 | 仅 OpenGL | 新增 **Vulkan** 后端（实验性，设置项 Default / Prefer Vulkan / Prefer OpenGL）；`com.mojang.blaze3d.opengl.*` 有平行 `…vulkan.*` | 决定「裸 GL 能不能用」 |
| 混合 | `DestFactor` / `SourceFactor` 两个枚举 | 合并为 **`BlendFactor`**；新增 **`BlendOp`**（默认 `ADD`）；`GlConst.toGl(DestFactor/SourceFactor)` → `toGl(BlendFactor[, BlendOp])` | 所有 blend 声明要改 |
| 纹理/顶点格式 | `TextureFormat` 枚举 + `VertexFormatElement` 内建元素 | 统一成 **`GpuFormat`** 枚举（`R8_UNORM`、`RGBA32_SINT`、`D32_FLOAT_S8_UINT`…）；`TextureFormat.RGBA8→RGBA8_UNORM`、`RED8→R8_UNORM`、`RED8I→R8_SINT`、`DEPTH32→D32_FLOAT` | 抓帧/自建 target 的格式常量全换 |
| 顶点格式 | 固定元素集（`DefaultVertexFormat.BLOCK/ENTITY/…` 由既有元素拼） | **部分重写**：不再有预置 `VertexFormatElement`，改为 `VertexFormat.builder().addAttribute(...)`，最多 **16** 个属性，每个至少 name + `GpuFormat`；`VertexFormat$IndexType` → **`IndexType`**，`VertexFormat$Mode` → **`PrimitiveTopology`**；一条 pipeline 最多 **16** 个 vertex buffer | 自研 `SkyMesh` 的顶点布局要重述 |
| pipeline 绑定 | `RenderPipeline` 自带 `samplers` + `UniformDescription` 列表；`ShaderManager` 编译 | 新增 **`BindGroupLayout`**（sampler 名 + uniform 描述），`RenderPipeline$Builder#withBindGroupLayout`，全部内建布局在 **`BindGroupLayouts`**；`RenderPipeline$Snippet` 可复用；同名 sampler/uniform 重复会编译期报错 | 13 条 pipeline 的声明全改 |
| 颜色附件 | 单个 `ColorTargetState` | 最多 **8** 个 `ColorTargetState`（`withColorTargetState(int, …)` / `withUnusedColorTargetState(int)`），数量必须与 `RenderPass` 的附件数一致 | 主线 S2 的「遮罩纹理替代 stencil」方案依赖它 |
| pass 区域 | 全 target | `CommandEncoder#createRenderPass` 可传 `$RenderArea` 矩形；`RenderPass` 支持 try-with-resources 的 close 回调 | 小 |
| 顶点上传 | `BufferBuilder` + `MeshData` + `MappableRingBuffer` + `uploadImmediateVertexBuffer/IndexBuffer` | 上述全部被 **`StagedVertexBuffer`** 取代；`uploadImmediate*` **删除**；`RenderBuffers#bufferSource/outlineBufferSource` → `stagedVertexBuffer` | `SkyMesh`/`SkyCloudMesh` 重写点 |
| 实体/特征渲染 | `FeatureRenderDispatcher` 持有 `SubmitNodeStorage` + **`MultiBufferSource$BufferSource`**；`renderSolidFeatures()` / `renderTranslucentFeatures()` / `renderTranslucentParticles()`；有 `ModelPartFeatureRenderer` | **`MultiBufferSource` 整套删除**，改为 `SubmitNode` / `FeatureRenderPhase` / `FeatureRenderer` 三件套；`FeatureRenderDispatcher#prepareFrame` + `$PreparedFrame#executeSolid/executeTranslucent/executeTranslucentAfterTerrain/executeAlwaysOnTop`；`ModelPartFeatureRenderer` **删除**；`ParticleFeatureRenderer`→`QuadParticleFeatureRenderer`；`BlockFeatureRenderer`→`BlockModelFeatureRenderer` | 若有 mixin 打到 `MultiBufferSource` 必须重打 |
| 文字 | `Font` 自带 draw 方法 | `Font` 的 draw **全删**，改 `prepareText` → `Font$PreparedText` → `Font$GlyphVisitor#acceptRenderable`；也可走 `OrderedSubmitNodeCollector#submitText` | 命令输出/调试文字 |
| Gizmo / 轮廓 | 直接画；`ShapeRenderer` 画 `VoxelShape` 轮廓 | Gizmo 走 **`GizmoFeatureRenderer`**（`GizmoProperties#setAlwaysOnTop`）；`ShapeRenderer` 被 **`ShapeOutlineFeatureRenderer`** 取代（`submitShapeOutline`） | 调试探针要改 |
| `RenderType` | `net.minecraft.client.renderer.rendertype.RenderType`（+`RenderSetup`/`OutputTarget`） | `RenderType#draw` → **`PreparedRenderType#drawFromBuffer(StagedVertexBuffer$ExecuteInfo)`**；`prepare()` 新增；`mode()`→`primitiveTopology()`；`bufferSize` 删除；`RenderTypes.textIntensity*`→`textGrayscale*`；`dragonRaysDepth` 并入 `dragonRays` | 面绘制入口 |
| GUI | `Minecraft#screen` / `Minecraft#gui.setOverlayMessage` | `Minecraft#gui.screen()`；HUD 独立成 **`Hud`**：`gui.hud.setOverlayMessage(...)`；`Minecraft#setScreen` → `gui.setScreen` | 客户端界面/命令反馈 |
| 组件颜色 | `ChatFormatting` | `ChatFormatting` 被「掏空」（不再是 `StringRepresentable`），一律用 **`Style#withColor/withBold/…`**；`TextColor` 提供 `ChatFormatting` 对应常量 | 命令输出配色 |
| `RenderSystem` | 有 `getModelViewMatrix()`、`flipFrame`、`getApiDescription`、`initBackendSystem(BackendOptions)` | `getModelViewMatrix` → `getModelViewMatrixCopy`；`flipFrame`/`getApiDescription` **删除**；新增 `shutdownRenderer`；`initBackendSystem` 不再收 `BackendOptions` | `SkyGlState` 相关 |
| 其它 | `GraphicsWorkarounds` | → `GlHeuristics` + `HintsAndWorkarounds`（`alwaysCreateFreshImmediateBuffer` 删除）；新增 `GpuDeviceLossException`、`GpuOutOfMemoryException`、`SurfaceException` | 低 |

出处：[26.1 → 26.2 primer](https://docs.neoforged.net/primer/docs/26.2/)（原文镜像：`raw.githubusercontent.com/ChampionAsh5357/neoforged-github/port/26.2/primers/26.2/index.md`，**B**）；[Fabric for 26.2](https://fabricmc.net/2026/06/15/262.html)（**A**）；26.1 侧现状见 [26.1.2 渲染分析](https://github.com/tt432/eyelib/blob/2b653dceb9e3db871851949545a5deddfdd8645a/docs/vanilla_research/geo_render/26.1.2.md)（**D**）。

#### 2.1.2 「不支持裸 OpenGL」这句话的确切范围（A）

[Basic Rendering Concepts（26.2）](https://docs.fabricmc.net/develop/rendering/basic-concepts) 顶部 WARNING 原文：

> *Use of raw OpenGL is not supported on Minecraft 26.2 as it has released with an optional Vulkan backend. Instead, you must use the `Blaze3D` abstraction layer, which sits between your code and the rendering backend (either OpenGL or Vulkan).*

同页 **26.1.2 版本**（[链接](https://docs.fabricmc.net/26.1.2/develop/rendering/basic-concepts)）**没有**这条 WARNING。→ 判定：**26.1 允许裸 GL；26.2 起不允许**。这条与主线 §6c 的 S1/S2 分叉判断吻合。

#### 2.1.3 一条容易被忽略的好消息 + 一条坏消息

- 好消息：`DepthStencilState` 在 26.2 仍「只有深度」，但 **`GpuFormat` 里存在带 stencil 通道的格式**（`D32_FLOAT_S8_UINT`，primer 原文举例）。也就是说**纹理侧可以分配 stencil 位**，只是 `DepthStencilState` 没有 stencil 比较/操作字段 → 结论不变（抽象层无法表达 stencil 测试），但「给不需要测试的 pass 分配带 stencil 的深度附件」是可行的。
- 坏消息：`MappableRingBuffer` + `mapBuffer` 那套「手工上传顶点」在 26.2 被 `StagedVertexBuffer` 吞掉，26.1 的写法在 26.2 编译不过（反之亦然）。**这就是 26.1 覆盖层必须存在的那一块。**

| 变化 | 内容 | 出处 |

| `assets/minecraft/shaders/core` 改名 | `rendertype_text`→`text`；`rendertype_text_background`→`text_background`；`…_see_through` 并入同文件 + `IS_SEE_THROUGH` 宏；`rendertype_text_intensity`→`text` + `IS_GRAYSCALE` | primer 26.2 **B** |

## 3. 26.2 → 26.3 的模组开发面变更清单

> 一句话：**26.3 同时动了渲染和注册**。Fabric 自己的说法是「technical changes are focused primarily on rendering (as always), new item components, world generation, and registries」（[Fabric for 26.3](https://fabricmc.net/2026/09/15/263.html)，**A**）。

### 3.1 渲染（26.2 → 26.3）—— 这是本模组前迁的唯一硬墙

#### 3.1.1 Renderpearl：整个 Blaze3D 渲染栈换包

渲染 API 从 Blaze3d 拆成独立项目 **Renderpearl**，所有渲染类迁到 `com.mojang.renderpearl`（[26.2→26.3 primer](https://docs.neoforged.net/primer/docs/26.3/)，**B**）：

| 包结构 | 含义 |
|---|---|
| `com.mojang.renderpearl.api.*` | 游戏直接交互的 API 元素 |
| `com.mojang.renderpearl.backend.*` | 真正与图形库通信的实现 |
| `com.mojang.renderpearl.frontend.*` | 已实现的 API（做校验） |

具体搬迁样本（primer 原文，**B**）：

```
com.mojang.blaze3d.GpuFormat              -> renderpearl.api.GpuFormat
com.mojang.blaze3d.IndexType              -> renderpearl.api.pipeline.IndexType
com.mojang.blaze3d.PrimitiveTopology      -> renderpearl.api.pipeline.PrimitiveTopology
com.mojang.blaze3d.buffers.GpuBuffer      -> renderpearl.api.buffers.GpuBuffer   (类 -> 接口)
com.mojang.blaze3d.buffers.GpuBufferSlice -> renderpearl.api.buffers.GpuBufferSlice
com.mojang.blaze3d.buffers.GpuFence       -> renderpearl.api.commands.GpuFence
com.mojang.blaze3d.systems.RenderPass     -> renderpearl.api.commands.RenderPass (接口化)
com.mojang.blaze3d.systems.RenderPassDescriptor -> renderpearl.api.commands.RenderPassDescriptor (改成 record)
com.mojang.blaze3d.opengl.*               -> renderpearl.backend.opengl.*
```

→ 对本模组：`API-MATRIX-26.2.md` §2 里列的**每一个** Blaze3D 符号（`GpuDevice`/`RenderPipeline`/`RenderPass`/`GpuTexture(View)`/`RenderTarget`/`PostChain`/`DepthStencilState`/`ColorTargetState`…）在 26.3 全部换包。**这是机械替换，但覆盖面 = 渲染层 100% 的文件。**

#### 3.1.2 抓帧机制被拆掉（对 skybox 影响最大）

- `RenderSystem#outputColorTextureOverride` 与 `#outputDepthTextureOverride` **完全删除**（primer 原文：「have been fully removed, closing one of the shenanigans when it came to writing to the GPU texture」）。
- 替代写法：**每个 try-with-resources 的 `RenderPass` 显式指定输出纹理**，例如
  `RenderSystem.getDevice().createCommandEncoder().createRenderPass(() -> "…", colorView, Optional.empty(), depthView, OptionalDouble.empty())`，配合 `FeatureRenderDispatcher.PreparedFrame`。
- 出处：primer 26.3 §「No More Texture Override Shenanigans」**B**。

> ⚠ 这条直接作废主线 `PORT-PLAN.md` §6 U4 的答案（「`RenderSystem.outputColorTextureOverride` 仍是 public 字段」）在 **26.3** 上的可用性：该字段在 26.2 存在、在 26.3 不存在。回迁 26.1 时它的存在性**待实测**（预计存在，因为机制正是 26.3 才拆的）。

#### 3.1.3 着色器语言（打破 26.2 的自研 shader）

| 变化 | 内容 |
|---|---|
| 引入 Shaderc / `GlslCompiler` | OpenGL 与 Vulkan 共用编译前端 |
| `#moj_import` → **`#include`** | 导入函数/片段的写法变了 |
| **`in`/`out` 必须写 `layout(location = N)`** | 顶点↔片段的传递按 location 对齐，变量名不再参与匹配 |
| 必需扩展 | 多数原版 shader 要求 `GL_ARB_separate_shader_objects` |
| 提供宏 | `RENDERPEARL_DEPTH_IS_ZERO_TO_ONE`、`RENDERPEARL_EXPLICIT_DEPTH_INVARIANCE`、`RENDERPEARL_INSTANCE_INDEX_INCLUDES_BASE_INSTANCE` |
| 新增的 shader 文件 | `blit_depth.fsh`、`integrate_depth.fsh`、`oit_composite.fsh`、`oit_depth_bounds_cull.fsh`；`shaders/include/{oit*.glsl, terrainglobals.glsl, texture_sampling.glsl}` |
| 改名 | `rendertype_clouds`→`clouds`、`rendertype_world_border`→`world_border`；`text_background` **删除**（并入 `text`） |
| 删除 | `assets/minecraft/post_effect/transparency.json`、`assets/minecraft/shaders/post/transparency.json` |

出处：primer 26.3 §「Shader Extensions and Layouts」+ 文件清单 **B**。

#### 3.1.4 顺序无关透明（OIT）

- 新的「improved transparency」= **Wavelet OIT**，三阶段：depth bounds / transmittance / accumulate；仅 accumulate 阶段写颜色。
- shader 侧用宏 `OIT_ALPHA_ONLY` / `OIT_ACCUMULATE`，需 `#include <minecraft:oit.glsl>`。
- Java 侧：`OitPipelineSet.builder(...)`（`withDepthBoundsModifier` / `withTransmittanceModifier` / `withAccumulateModifier`）+ `RenderSetup#setOitPipelines(...)` + `PreparedRenderType#drawFromBufferOit(...)`。
- 出处：primer 26.3 §「Order Independent Transparency (OIT)」**B**。

> 对 skybox 的意义：**「半透明/云/星空要不要接 OIT」是 26.3 独有的设计岔口**，26.1/26.2 都没有。若走 OIT，`FeatureRenderDispatcher#renderAllFeatures` 会重复渲染同一 phase，必须改用 `prepareFrame` + 逐 phase 执行。

#### 3.1.5 其余渲染变动（点到为止）

| 变化 | 内容 | 影响 |
|---|---|---|
| **SDL 取代 GLFW** | LWJGL 改用 SDL3；键码语义变为 scancode；`KeyEvent.key`=SDLScancode、`keycode`（原 `scancode`）=SDLKeycode；鼠标键常量全变；文本输入必须通知 `TextInputManager`（`Minecraft#onTextInputFocusChange`） | 只要用 `InputConstants` 就基本无痛；硬编码 GLFW 键码会坏 |
| Feature phase 重命名 | `SubmitNodeCollection#seeThroughNameTags`→`seeThrough`；`gizmos`→`translucentGizmos`；`alwaysOnTop`→`alwaysOnTopGizmos`；实心 gizmo 并入 `solid` | mixin 点位要重打 |
| 物品四边形 | 新增 **`ItemQuads`**（`solid`/`translucent`/`all` 三组），`ItemModel` 应缓存 | 低 |
| 破坏覆盖层 | 改走 `OrderedSubmitNodeCollector#submitCrumblingOverlay`；`submitModel/submitModelPart` 不再收 crumbling overlay | 低 |

出处：primer 26.3 **B**（`net.minecraft.client.renderer.state.level` 等条目）。

## 4. 结论：以 26.2 为母版，回迁 26.1 / 前迁 26.3 的可行性

### 4.1 一张表看完

差异强度：★☆☆ 小（改名/参数级，≤ 一屏）；★★☆ 中（签名或包变化，需适配）；★★★ 大（架构变化，需整类重写）。

| 子系统 | 26.1 差异 | 26.3 差异 | 建议做法 | 理由（一句话） |
|---|---|---|---|---|
| **注册**（方块/物品/BE/数据组件） | ★★☆ `BlockIds`/`BlockItemIds`/`ItemIds` 拆分、`valueLookupBuilder` 移除、`ColorCollection` 化 | ★★☆ `Block` 的 `Codec` 与 `block_type` 注册表删除；可重载注册表改写 datagen；`ContextAwarePredicate` 删除 | **共享代码 + 版本目录覆盖**（把 id 常量抽成 `Ids` 接口 + 各版本 20 行实现） | 两边都只是「注册写法」不同，逻辑同一套 |
| **资源包**（pack.mcmeta/模型/贴图） | ★☆☆ 88.0；原版 shader 文本族改名（不影响自研） | ★★★ 97.1（9 次 bump）；shader `#include` + 强制 `layout(location)`；`text_background` 删除；图集/palette 元数据 | 26.1 **共享**；26.3 **版本目录覆盖（整套资源包）** | 26.3 的资源包与 26.2 不同源，只能各存一份 |
| **命令** | ★☆☆ `/unpublish` 新增；`ChatFormatting`→`Style` | ★☆☆ `/compute` 新增；命令树/参数序列化未见变更 | **共享代码** | 两个方向都没有命令 API 破坏性变更 |
| **网络** | ★☆☆（≈0）`CustomPacketPayload` 无变化 | ★☆☆ 仅新增包 + `SignText#STREAM_CODEC` | **共享代码** | 三版之间 `CustomPacketPayload` 全程稳定 |
| **渲染 — 管线/状态声明** | ★★☆ `BindGroupLayout`、`GpuFormat`、`BlendFactor`、动态 `VertexFormat`、`IndexType`/`PrimitiveTopology` 拆出、MRT | ★★★ 全部搬到 `com.mojang.renderpearl.*`（包级改名 + 接口化） | 26.1 **版本目录覆盖**（pipeline 声明 1–2 个文件）；26.3 **整类分叉** | 26.1 只是「写法不同」；26.3 是「换项目」 |
| **渲染 — 顶点提交/网格** | ★★☆ `StagedVertexBuffer` 取代 `BufferBuilder`+`MappableRingBuffer`+`uploadImmediate*` | ★★☆ 随包搬迁；物品侧引入 `ItemQuads` | 26.1 **版本目录覆盖**（`SkyMesh`/`SkyCloudMesh` 的提交层）；26.3 跟随分叉 | 顶点数据本身不变，只有「怎么交给 GPU」变了 |
| **渲染 — 抓帧/后处理** | ★★☆ `MultiBufferSource` 删除、`FeatureRenderDispatcher#prepareFrame` 新分相、`PostChain#addToFrame` | ★★★ **`outputColorTextureOverride` 删除**（抓帧机制必须改写）+ OIT | 26.1 **版本目录覆盖**；26.3 **整类分叉 + 机制重设计** | 26.3 把本模组的骨架（换 framebuffer）从「字段覆盖」变成「pass 显式指定附件」 |
| **渲染 — 帧内插入/mixin** | ★☆☆ `FrameGraphBuilder`/`FramePass` 26.1 已有 | ★★☆ `SkyRenderState` 颜色 `int`→`Vector4fc`、`LevelRenderState` 字段增删；SDL 换输入 | **26.2 主干 + 版本覆盖点位** | 帧图在 26.1 就位；26.3 只动「取什么数据」 |
| **渲染 — 光影（Iris）** | **不测** | **不测** | **只在 26.2 编入**，26.1/26.3 用空实现占位 | 用户已定：26.1/26.3 不做 Iris 测试 |

### 4.2 可行性判断（直给）

1. **回迁 26.1：可行，且比预期便宜。**
   26.1 已是同一套 `RenderPipeline`/`RenderPass`/`GpuDevice`/`FrameGraph`/`SubmitNode` 范式（§0 第 2 条），**没有「退回 1.21.1 状态机」这一步**。需要版本化的只有三小块：
   - pipeline 的 `samplers`+`UniformDescription` vs `BindGroupLayout`（§2.1.1）；
   - 顶点提交 `MappableRingBuffer` vs `StagedVertexBuffer`（§2.0 表）；
   - `BlockIds` 注册写法（§2.2）。
   其余（配置、命令、网络、环境数学、自定义天空盒注入）按 §4.1 全部共享。**粗估 5–10 个文件进 `src/26.1/java`。**

2. **前迁 26.3：可行，但渲染层等价于「再移植一次」。**
   障碍是三条叠加：Renderpearl 包级搬迁（机械但铺满渲染层）+ `outputColorTextureOverride` 删除（改机制）+ shader 语法 `#include`/`layout(location)`（13 条 pipeline 全改）。且新增 OIT 岔口、`SkyRenderState` 字段类型变化。
   → **不建议**用「共享主干 + 少量覆盖」硬顶；**渲染层整类下沉到 `src/26.3/java`**，A/B 档（配置/命令/网络/天空盒注入/环境数学）共享。

3. **不需要为 26.1 引入 Vulkan 分支。** 26.1 只有 OpenGL 后端（§1.1、§2.1.2），`GlStateManager` 在 26.1 仍是合法路径；但 S2 路线（一律走抽象层）在 26.1 同样成立 → **不要**为 26.1 重开 S1 裸 GL 分支，否则要维护三条渲染实现。

4. **26.2 母版的选择是对的。** 三个版本里 26.2 是唯一「既有 Vulkan/抽象层、又没被 Renderpearl 拆过」的版本，是唯一的「中间态」，天然适合当母版。

### 4.3 建议的落地顺序（P9 细化）

1. 先用**同一套探针**在 26.1.2 / 26.3 上各跑一次 `jar tf` + `javap`，产出 `API-MATRIX-26.1.md` / `API-MATRIX-26.3.md`，把本文件 §5 的「待实测」清空。
2. 26.1：先做 `Identifier` 零工（已成立）→ 再改 `BlockIds` 注册 → 最后套渲染覆盖层。
3. 26.3：先做「包名批量替换」（`blaze3d` → `renderpearl`）拿到编译错误清单 → 再改抓帧机制 → 最后重写 shader 资源包。
4. 26.1 / 26.3 验收按 `PORT-PLAN.md` §4 第 4 条：**原版渲染 + 命令 + 多人**，光影栏写「未测（按计划跳过）」。
